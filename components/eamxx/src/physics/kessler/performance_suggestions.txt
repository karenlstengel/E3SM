Kessler Kokkos Performance Suggestions
=======================================

Last updated 2026-10-28 against kessler_functions_impl.hpp at commit
49bf6ccdde ("kessler CPP fixes and consistency"). Performance numbers
come from GK_perf_utils/kessler_perf_trends.md.

A. CURRENT STATE
================

Done and present in the code:

1. SCRATCH VIEW PRE-ALLOCATION (Plan A from the 2026-09-22 notes)
   The 10 scratch arrays are in KMF::Workspace (kessler_functions.hpp)
   and are passed to kessler_run as `const Workspace& ws`. The process
   interface carves them out of one ATMBufferManager allocation in
   requested_buffer_size_in_bytes()/init_buffers()
   (eamxx_kessler_process_interface.cpp), the same way P3 and SHOC
   do. driver_kessler.cpp can build the workspace either way
   ("managed" or "carved") and checks that both give the same answer.
   The 09-22 call-site and z-vs-dz problems are fixed: kessler_run
   now takes z_mid, and run_impl passes pref, ncols and pk.

2. cpair/rair ARE SCALARS
   cpair and rair are passed to kessler_run as Real scalars (there is
   no KesslerData struct). xk = cp/R and f5_dk = 4093*lv/cp are computed
   once on the host.

3. dt0 IS RE-CHECKED AGAINST CFL EVERY SUB-CYCLE
   kessler_recompute_dt0 does this, matching the Fortran reference. The
   "bad time splitting" abort (dt0 < 1e-12) has also been restored.

Corrections. The previous version of this file said the items below
were done, but they are NOT in the code:

- Old item 2, CHECK_INTERVAL=4. The convergence reduction
  (kessler_converge) still runs every iteration, and each run is a
  device-to-host sync.
- Old item 7, mask-guarded early exit. No sub-cycle kernel skips
  converged columns. kessler_precl_accum, kessler_sed_inner,
  kessler_sed_toa, kessler_micro, kessler_velqr_update and
  kessler_recompute_dt0 all do the full computation for every
  column on every iteration, including every pow/exp call.
  kessler_micro only uses `msk` to throw the result away for
  converged columns.
- Old item 8, fence removed before the sub-cycle loop. Both fences
  are still there: one after kessler_init_fields and one after
  kessler_init_dt0. kessler_check_dt0 (added later for the
  bad-time-splitting abort) also reduces into a host scalar, which
  syncs anyway.
- "f5 was dropped." ws.f5 / Buffer::f5 is still in the Workspace and is
  still sized and carved (num_2d_vector = 6), but kessler_run never
  uses it. That wastes ncols*nlev_packs Packs of buffer memory.
- driver_kessler.cpp's --help text still talks about a "TEMPORARY
  'n_iter < 10'" limit. The limit is now n_iter < 100000.


B. THE CPU PERFORMANCE PROBLEM
==============================

Symptoms (ne60, s per simulated day, subcycles = 1, kessler::run):

                 Fortran   C++
  cpu, noRain      3.5     3.1
  cpu, rain       11.8    65.5   (5.5x slower)
  gpu, rain       20.0     6.8   (C++ is the fastest option)

  - The gap shows up only with rain, and it grows with grid size:
    about 3-4x at ne16/ne30 and about 5x at ne60.
  - Without rain, the C++ and Fortran CPU kernels take the same time
    (e.g. 0.13 vs 0.13 s/day at ne30 sc1).
  - Rain cost is set by the number of CFL sub-steps, not by how many
    times Kessler is called (trend 7 in kessler_perf_trends.md).

Likely cause: sub-cycling runs as one loop over all columns instead of
one loop per column.

  The Fortran reference (atmospheric_physics/schemes/kessler/kessler.F90)
  runs its sub-cycle `do while` loop INSIDE `do col = 1, ncol`. Each
  column does only its own sub-cycles: a dry column has velqr = 0, so
  dt0 = dt and it finishes in 1 pass.
      Fortran work = SUM over columns of each column's sub-cycle count

  The C++ code runs the `while (!all_converged)` loop on the host,
  outside every kernel. Each pass sweeps all ncols * nlev_packs, and
  converged columns are not skipped (see the corrections in A).
      C++ work = MAX over columns of the sub-cycle count * ncols

  With rain in 3-12% of columns, max * ncols is several times the sum.
  This fits every symptom above:
    - noRain: max = sum = 1, so C++ ties with Fortran.
    - A bigger grid has more columns per rank, so the worst column on
      each rank needs more sub-cycles.
    - On GPU all columns run at once, so the time is set by the slowest
      column either way. The extra work lands on idle threads, which
      is why the GPU number looks good.

Secondary CPU costs. These make every extra pass more expensive:
  - Memory. Each pass runs about 7 separate kernels, and each one
    streams the full (ncols, nlev) fields. Fortran keeps one column
    (nlev levels) in L1 cache for all of its sub-cycles. At ne60 on
    128 ranks (~1500 columns per rank), each field is ~0.7-0.9 MB (58-72 levels) and
    the ~12 fields used per pass don't fit in L1/L2.
  - A host sync every pass (kessler_converge), plus kernel launch
    overhead (OpenMP fork/join, if the CPU build uses OpenMP).
  - The RangePolicy kernels compute col = idx / nlev_packs and
    kp = idx % nlev_packs on every iteration, which can stop the
    compiler from vectorizing the inner loop.
  - The pow/exp calls in kessler_micro and kessler_velqr_update
    (about 4 pow and 1 exp per level per pass) run on dry columns
    too, where qr = 0.


C. TODO: CONFIRM THE CAUSE
==========================

[ ] C1. Count the extra column passes. Do this behind a compile-time
        flag, e.g. KESSLER_SUBCYCLE_STATS, so production is unaffected.
        - Every mask is 1 at the start, and kessler_converge returns
          n_active after each pass. So
              col_passes = ncols + sum over iterations of n_active
          with no extra kernel needed.
        - Print n_iter, ncols, n_iter*ncols, col_passes and
          waste = n_iter*ncols / col_passes.
        - Optionally also print a histogram of per-column sub-cycle
          counts. That needs one int per column in the Workspace,
          incremented where mask = 1.
        Expect waste >> 1 with rain and = 1 without rain.

[ ] C2. Make driver_kessler.cpp's rain look like the real runs.
        - At the moment --rain puts rain in every other column (50%),
          which understates the waste. Add a --rain-frac F option
          (3-12% to match days 10-15 of the dcmip2016 runs).
        - Add a Kokkos::Timer around the kessler_run loop.
        - Set ncols/nz/dt to an ne60 CPU rank: ~1500 columns per rank
          at 128 ranks, and the case's nlev and physics dt.
        - Build with build_driver_kessler.sh --case-build pointing at a
          CPU case (the default is the ne16 GPU case). Run it with 1
          rank, using the same Kokkos backend and thread count as the
          production CPU runs.

[ ] C3. Get the per-kernel CPU breakdown with Kokkos Tools
        (kp_kernel_timer) or with EAMxx timers around each kernel in
        the sub-cycle loop. Check whether time is spread evenly over
        the passes (wasted work) or concentrated in kessler_converge
        (sync and launch overhead).

[ ] C4. Check the CPU build configuration:
        - SCREAM_PACK_SIZE (in CMakeCache.txt) and how much padding
          that leaves for nlev.
        - The Kokkos backend (Serial or OpenMP) and OMP_NUM_THREADS
          per rank in the 128-rank CPU runs.
        - Whether the compiler vectorized kessler_micro: use
          -qopt-report or -fopt-info-vec, depending on the compiler.

[ ] C5. Read off the bound: estimate C++ time with the waste removed as
        measured time / waste from C1. If this lands near Fortran's
        11.8 s/day at ne60 rain, the loop structure is the whole story.
        If not, the secondary costs matter and should be fixed too.


D. TODO: POSSIBLE FIXES, IN PRIORITY ORDER
==========================================

[ ] D1. (Recommended) Move the sub-cycle loop into the kernel, one team
        per column, like Fortran.
        - Replace the host while loop and its ~8 kernels per pass with
          one TeamPolicy(ncols, AUTO) kernel. Each team runs its own
          column's `while (|dt - time_counter| > 1e-5)` loop.
        - Inside the loop, the level loops become TeamVectorRange or
          ThreadVectorRange over packs, the CFL min becomes a team
          parallel_reduce, the shift_left/shift_right stencil stays as
          it is, and team_barrier()s go between the sed, micro and
          velqr stages.
        - CPU: work becomes the sum over columns, and each column's
          data stays in cache.
        - GPU: removes the host round-trip and launch overhead every
          pass. Time is still set by the slowest column, so GPU
          performance should not get worse.
        - dt0, mask, time_counter and precl_acc become team-local
          scalars. velqr and sed could move to team scratch
          (nlev_packs Packs each), which would shrink the Workspace.
          r, rhalf and pc only depend on inputs, so they could be
          computed on the fly.
        - Remove the "bad time splitting" and "cannot converge" checks
          from the host loop. Have the kernel set an error flag that
          is reduced once after the kernel finishes.
        - Validate with driver_kessler.cpp (host vs device, strided
          tracers, rain) and against the Fortran bridge.

[ ] D2. (Stopgap if D1 is delayed) Make converged columns cheap.
        - Return early when mask(col) == 0 in kessler_precl_accum,
          kessler_sed_inner, kessler_sed_toa, kessler_micro,
          kessler_velqr_update and kessler_recompute_dt0. This is the
          old item 7, which was never actually committed.
        - This removes the pow/exp cost for dry columns, but every pass
          still makes the separate sweeps over memory and pays the
          launch and sync cost. Expect a partial fix only.
        - Check that precl_acc / precl stay correct, because
          kessler_precl_accum writes precl even for masked columns.

[ ] D3. (Stopgap, combine with D2) Compact the active columns.
        - Once the first pass is done, build a list of the columns that
          are still active (a parallel_scan over mask) and run the
          sub-cycle kernels only over that list.
        - When only 3-12% of columns rain, this gets most of D1's
          saving on CPU without restructuring the code.
        - Rebuild the list every few passes, as columns converge.

[ ] D4. Reduce the host syncs. Check convergence every N passes (the
        old item 2, which was also never committed). Only safe after
        D2, so that the extra passes don't change a converged column.
        Not needed if D1 is done.

[ ] D5. Fuse kernels within a pass. Fold kessler_update_time,
        kessler_velqr_update and kessler_recompute_dt0 into one team
        kernel, and kessler_sed_inner and kessler_sed_toa into one.
        This cuts the number of sweeps over memory. Not needed if D1
        is done.

[ ] D6. Small cleanups:
        - Remove the fences after kessler_init_fields and
          kessler_init_dt0. The kessler_check_dt0 reduction already
          syncs.
        - Remove ws.f5 / Buffer::f5 (set num_2d_vector = 5; update
          init_buffers, requested_buffer_size_in_bytes and
          driver_kessler.cpp's make_workspace).
        - Use MDRangePolicy or TeamPolicy instead of the idx / and %
          in the RangePolicy kernels.
